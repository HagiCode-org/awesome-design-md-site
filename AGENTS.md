# awesome-design-md-site - Agent Configuration

## Root Configuration

Inherits all behavior from `/AGENTS.md` at the monorepo root. Local rules extend or override the root file for this repository.

## Project Context

`awesome-design-md-site` is an Astro-based static gallery site for browsing design system entries from the upstream `awesome-design-md` repository. Content is sourced from a vendor git submodule.

## Working Directory

Run commands from `repos/awesome-design-md-site/`.

## Key Commands

```bash
pnpm install
pnpm run dev
pnpm run build
pnpm run i18n:check
pnpm run previews:verify
pnpm test
pnpm run typecheck
pnpm run previews:render                    # maintainer only: needs Chromium and fonts access
git submodule update --init --recursive   # needed for real gallery content
```

Requires Node.js 24+. `pnpm run build` first runs `previews:verify`, then also runs `scripts/verify-promoto-build.mjs` and `scripts/verify-footer-build.mjs` against `dist/`.

## Key Paths

- `src/pages/`: Astro routes (gallery, detail pages)
- `src/pages/[locale]/` and `src/pages/en/`: localized routes (ten locales, default `en` unprefixed per `astro.config.mjs`)
- `src/components/`: Astro/React components; `src/components/gallery/` holds the gallery workbench (search toolbar, saved layouts, preview switcher, document tabs/outline, card-to-detail view transition) with pure logic in sibling `*.ts` modules and `*.test.ts(x)` tests
- `src/lib/content/`: build-time catalog scanner for the vendor submodule
- `src/i18n/locales/`: locale YAML (managed via `hagi18n`); `src/i18n/generated/` is generated by `pnpm run i18n:generate`
- `.github/workflows/`: gh-pages deploy workflow (runs `pnpm run build` with submodules, then publishes `esa.jsonc` from `.github/gh-pages/` plus `dist/` to `gh-pages`)
- `vendor/awesome-design-md/`: git submodule content source
- `public/preview-images/` and `src/data/preview-images.json`: generated AVIF previews and their manifest (written by `scripts/render-preview-images.mjs`, checked by `scripts/verify-preview-images.mjs`)
- `DESIGN.md`: site shell design system (separate from vendor entry DESIGN.md files)

## Agent Guidelines

- This repos's root `DESIGN.md` describes the gallery site shell itself, not upstream design entries.
- Vendor content under `vendor/awesome-design-md/` is a git submodule; do not edit it directly.
- Gallery previews are locally rendered AVIF images, never live iframes. Do not hand-edit `public/preview-images/` or the manifest; after a vendor change run `pnpm run previews:render`, then `pnpm run previews:verify`.
- Keep the gallery site shell design (two-theme colors, typography, search, preview tabs) aligned with `DESIGN.md`.
- Use `pnpm run i18n:check` to validate locale consistency.
- Footer, favicon, analytics, RSS and `llms.txt` come from `@hagicode/hagilight` / `hagilight-core` (configured in `astro.config.mjs`); upgrade them together and adjust the build verification scripts if footer or promoto output changes. Analytics renders the shared `@hagicode/hagilight-core` components directly (no local wrappers; PostHog is injected by `hagilight()`), and the site identifies itself to the footer/promoto banner with `siteId` `awesome-design-gallery` so it is absent from its own Ecosystem Sites list.

## PostHog Events

Site-level events are sent only through `captureSiteEvent` in `src/lib/posthog-events.ts`, which reads the frozen `SITE_POSTHOG_EVENTS` table. The wrapper never throws, sends nothing without `window.posthog` or when the visitor has opted out, and drops every property that is not allowlisted (strings are capped at 128 characters). Event names are snake_case, object first. Tests in `src/lib/posthog-events.test.ts` cover the wrapper contract and the exact allowlisted payloads.

| Event | Fires when | Properties |
|-------|-----------|------------|
| `design_doc_tab_changed` | The visitor selects a document tab that differs from the active one (re-selecting the active tab sends nothing) | `tab`: `readme` or `design` |
| `design_md_copied` | The DESIGN.md copy succeeds (a failed copy sends nothing) | `slug`: directory entry slug |
| `design_md_downloaded` | A `[data-download-design]` link is activated, including clicks on elements nested inside it | `slug`: directory entry slug |
| `design_search_used` | The search query settles (400 ms without change) to a non-empty value that differs from the last reported settled query; the query restored from `?q=` on load is not counted | `results_count`: non-negative integer |

Deduplication rule: the four events above are the canonical record of those actions. The DESIGN tab, copy and download controls currently carry no `data-ga-*` marker, so no `cta_click` event is produced for them; if a marker is added later, a click may produce both the business event and `cta_click`. Dashboards must not add these business events to `cta_click` counts. The search term and any URL are never sent.

## Package management

- The repository uses pnpm, pinned in `package.json` `packageManager`. Run `corepack enable` once, then `pnpm install`. `pnpm-lock.yaml` is the only lockfile; do not commit `package-lock.json`.
- Settings live in `pnpm-workspace.yaml`. `allowBuilds` lists the dependencies whose install scripts may run (reviewed individually, `false` means reviewed and denied); review any new dependency that has an install script and add it there.
- A local registry mirror belongs in `~/.npmrc` only. Never commit a `registry=` line or a mirror URL; `pnpm run check:registry` (also run in CI) fails on any non-`registry.npmjs.org` `tarball` in the lockfile and on mirror hosts in tracked files.
- Undeclared imports fail under pnpm's strict layout: declare the package instead of hoisting it.
